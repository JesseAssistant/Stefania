# Stefania's Nanabo World

Личная мини-игра для iPhone: Stefania — хозяйка базы забавных существ Нанабо. Это **PWA**: открывается в Safari, добавляется на экран «Домой», после первой загрузки работает **без интернета**, а весь прогресс хранится на самом телефоне.

> Всё в игре — оригинальное: персонажи, графика (SVG/CSS), музыка и звуки (WebAudio) придуманы и нарисованы для этой игры. Никаких чужих персонажей, лого, картинок или звуков.

## Установка на iPhone

1. Открой адрес игры в **Safari** (именно Safari — только он умеет «Домой»).
2. Нажми «Поделиться» → **«На экран „Домой“»** → «Добавить».
3. Открой игру **один раз с интернетом и дождись главного экрана** — в этот момент она сама загружает всё нужное для офлайна.
4. Дальше можно играть в самолёте. Иконка на экране — как у обычного приложения, без адресной строки.

Внутри игры есть экран «Установка» с теми же шагами.

## Сохранения — самое важное

Игра хранит прогресс на телефоне (IndexedDB + зеркало в localStorage), пишет его после каждого действия и держит предыдущую версию записи на случай сбоя.

**Но iOS может удалить данные сайта**, если долго не открывать игру в Safari (около 7 дней) — для игры, добавленной на экран «Домой», этого правила обычно нет, но гарантий дать нельзя. Поэтому:

- раз в несколько дней заходи в **Настройки → Сохранения → «Сохранить файл»** и сохраняй `STEFANIA_SAVE.json` в «Файлы» / iCloud Drive;
- перед любым обновлением, сбросом или чисткой Safari — тоже сохраняй файл;
- при запуске игра сама делает копию, если с прошлой прошло больше 12 часов (хранит 7 последних), а копии «перед импортом», «перед сбросом», «перед обновлением данных» и ручные не удаляются;
- восстановление: «Сохранения» → «Выбрать файл…» → проверка → «Заменить прогресс». Перед заменой игра сохраняет копию текущего прогресса.

Подробности: [docs/SAVES.md](docs/SAVES.md) (формат, проверки, миграции) и [docs/RECOVERY.md](docs/RECOVERY.md) (что делать, если что-то пошло не так).

## Для разработки

Нужен Node 22+.

```bash
npm install
npm run typecheck     # TypeScript
npm test              # 87 юнит/интеграционных тестов и тесты миграций (node:test + tsx)
npm run build         # → dist/  (относительные пути, работает из любого подкаталога)
npm run preview       # http://localhost:4173/stefania-nanabo-world/
npm run test:e2e      # Playwright: установка, офлайн, подпуть, обновление, сохранения
npm run ci            # всё вместе
```

`npm run build:e2e` собирает отдельную сборку с тестовым хуком `window.__game`; **в `dist/` этого хука нет** (проверяется в CI).

### Публикация на GitHub Pages

1. Создай репозиторий `stefania-nanabo-world` (подкаталог `/stefania-nanabo-world/` — любое другое имя тоже подойдёт: пути в сборке относительные).
2. В **Settings → Pages → Source** выбери **GitHub Actions**.
3. Запушь в `main` — воркфлоу `.github/workflows/ci.yml` прогонит проверки и выложит `dist/`.

Автоматически ничего не публикуется: это делается только после твоего push.

### Как выходят обновления

Service Worker кеширует все файлы версии целиком. Новая версия скачивается в фоне, **но не включается сама**: в игре появляется плашка «Доступна новая версия. Прогресс сохранится» и кнопка «Обновить». Перед обновлением игра дописывает сохранение на диск. Старые данные при необходимости приводятся к новой схеме миграциями (см. docs/SAVES.md).

## Что проверено, а что нет (честно)

Проверено автоматически:
- 87 юнит- и интеграционных тестов: экономика, награды (идемпотентность), гардероб, уровни и звёзды, сундуки (детерминированный ГСЧ), экспорт/импорт, миграция старого формата, резервные копии, маршруты, правила всех 8 игр;
- 12 e2e-сценариев в настоящем браузере (Chrome, экран 390×844, мобильный user-agent): первый запуск из подкаталога, все экраны без ошибок консоли, перезагрузка, офлайн с Service Worker, обновление версии, манифест и иконки, **главный сценарий «500 бананов → костюм → лаборатория → улучшение → экспорт файла → обновление → импорт старого файла → идентичный прогресс»**, битые и подделанные файлы, резервные копии, песочница, прохождение настоящего уровня.

Известные ограничения:
- **Не проверялось на реальном iPhone и в настоящем Safari/WebKit.** Тесты шли в Chromium с имитацией телефона. Установка «На экран Домой», поведение хранилища iOS и звук нужно один раз проверить руками.
- **Типы интерфейса**: в среде без сети не было `@types/react`, поэтому React-экраны проверялись против упрощённого описания типов (`types-shim/`). Логика, хранилище и данные проверяются полноценным `tsc`. Команда `npm run typecheck` в CI использует настоящие типы и может найти мелкие замечания, которых не видно локально.
- Тесты написаны на встроенном `node:test`, а не на Vitest (так не нужны сетевые зависимости).
- Баланс мини-игр (скорость падения, число ходов и т. п.) подобран расчётом и проверен на достижимость трёх звёзд, но **живой игрой не обкатан** — возможно, что-то захочется упростить или усложнить.
- Если закрыть игру посреди приготовления блюда, часть ингредиентов не возвращается.
- Не требовалось и не делалось: аккаунты, сеть, реклама, покупки за деньги.
