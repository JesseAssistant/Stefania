# Сохранения: хранение, файл, проверки, миграции

## Где лежит прогресс

| Место | Что | Зачем |
|---|---|---|
| IndexedDB `stefania-world`, хранилище `kv`, ключ `save` | текущая запись | основное хранилище |
| там же, ключ `save.prev` | предыдущая запись | если последняя повредилась при записи |
| `localStorage` `stefania.save.mirror.v1` | зеркало текущей записи | запасной путь, если IndexedDB недоступна |
| IndexedDB, хранилище `backups` | резервные копии | восстановление из интерфейса |
| IndexedDB, хранилище `quarantine` | записи, которые не удалось прочитать | ничего не теряется молча: повреждённое откладывается, а не стирается |

Запись — это оболочка `{ wrapper, schemaVersion, gameVersion, revision, savedAt, checksum, state }`. `checksum` — SHA-256 по каноническому JSON состояния; при чтении он проверяется, и тихая порча данных обнаруживается.

### Порядок чтения при запуске

Читаются три источника — `save`, зеркало localStorage и `save.prev`. Каждый проверяется (структура + контрольная сумма); нечитаемые уходят в `quarantine`. Из читаемых берётся **самая свежая ревизия** (при равенстве — основное хранилище); если использовано не основное, игра показывает предупреждение. Если ни один не читается, пробуются резервные копии от новых к старым. Новая игра создаётся **только** когда не прочитано вообще ничего; в этом случае игрок видит предупреждение, а повреждённые данные остаются в `quarantine`.

### Запись

- Запись идёт через очередь: всегда пишется самое свежее состояние, интерфейс не блокируется.
- Сохранение происходит после каждого действия (`GameStore.tx`) и при уходе приложения в фон (`visibilitychange`/`pagehide` → `flush`).
- Ошибка записи не глотается: статус `error`, повтор с задержкой, а после второй неудачи — красная плашка «Не удаётся сохранить прогресс» с кнопкой в центр сохранений, откуда можно выгрузить файл.
- Состояние песочницы (свободной игры) **не пишется никогда**: это копия в памяти.

## Файл `STEFANIA_SAVE.json`

```jsonc
{
  "format": "STEFANIA_WORLD_SAVE",
  "schemaVersion": 1,
  "gameVersion": "1.0.0",
  "player": { … }, "currencies": { … }, "characters": { … }, "wardrobe": { … },
  "base": { … }, "levels": { … }, "quests": { … }, "achievements": { … },
  "metadata": { "revision": 123, "processedEvents": [ … ], "rng": { … }, … },
  "exportedAt": "2026-11-15T17:00:00.000Z",
  "integrity": { "algorithm": "sha256", "checksum": "…", "sections": 17 }
}
```

Контрольная сумма считается по всем полям, кроме `exportedAt` и `integrity`. Файл читаемый (с отступами), поэтому его можно открыть в текстовом редакторе, но **править руками нельзя**: любая правка сломает сумму, и импорт откажет.

Экспорт: «Сохранить файл» (меню «Поделиться» iOS → «Сохранить в Файлы»), «Скачать файл», «Скопировать текст».

## Импорт — конвейер проверок

`parseSaveText` проходит стадии по порядку и останавливается на первой ошибке; текущий прогресс **не меняется до самого конца**.

1. `parse` — это JSON?
2. `format` — наш формат (принимаются и старые названия формата)?
3. `structure` — есть версия схемы, нужные разделы?
4. `integrity` — контрольная сумма совпала? (файл без суммы — старый формат — принимается с предупреждением)
5. `compat` — файл не новее игры? Файл от более новой версии **не принимается** с просьбой обновить игру.
6. `migrate` — цепочка миграций до текущей схемы.
7. `validate` — `hydrate` (дополнение недостающих полей значениями по умолчанию) и строгий валидатор: все разделы на месте, валюты — неотрицательные целые, уровни, звёзды (0–3), журнал событий, ревизия, структура гардероба/базы/инвентаря.
   `hydrate` ничего не стирает: недостающие записи (новые персонажи, комнаты, уровни, поля) добавляются со значениями по умолчанию, а надетые вещи, которых нет в игре, просто снимаются с персонажа. Остальные данные остаются как есть.

После успешной проверки пользователю показывается сравнение «сейчас → из файла». Нажатие «Заменить прогресс»:

1. делается **резервная копия текущего прогресса** (`import`, не удаляется);
2. состояние заменяется, `revision` становится больше обоих;
3. запись принудительно сбрасывается на диск и **перечитывается для проверки** (`verifyPersisted`).

## Миграции

Реестр — `src/storage/migrations/index.ts`. Сейчас: `0 → 1` (прототип → схема 1; тест на реальном фикстуре `tests/migration/fixtures/v0_prototype.json`).

Правила миграции:
- получает глубокую копию, исходные данные не меняются;
- переносит всё: валюты, персонажей, одежду, прогресс, достижения; **не обнуляет** и не «сбрасывает» ничего;
- перед миграцией сохранения при запуске игра делает копию `migration`.

Как добавить схему 2:
1. `SCHEMA_VERSION = 2` в `src/config.ts`;
2. `src/storage/migrations/v1_to_v2.ts` + строка в `MIGRATIONS`;
3. тест в `tests/migration/` с файлом схемы 1, сохранённым **до** изменений (положи его в `fixtures/`, не перегенерируй);
4. новые необязательные поля добавляй в `hydrate()` со значениями по умолчанию.

Новая версия игры **всегда** читает файлы всех предыдущих схем; старая версия игры отказывается от более новых файлов, а не портит их.

## Идемпотентность наград

`metadata.processedEvents` хранит идентификаторы уже засчитанных попыток (`run:…`, `arcade:…`, `cook:…`, открытия сундуков). Повторная отправка той же попытки, двойной тап или импорт файла не дадут награду второй раз. Список ограничен 4000 последних записей.

## Резервные копии

| Причина | Когда создаётся | Удаляется? |
|---|---|---|
| `auto` | при запуске, если прошло > 12 ч | да, остаются 7 последних |
| `manual` | кнопка «Создать сейчас» | нет |
| `import` | перед импортом файла | нет |
| `restore` | перед восстановлением из копии | нет |
| `migration` | перед миграцией данных | нет |
| `reset` | перед сбросом прогресса | нет |
