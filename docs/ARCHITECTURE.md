# Архитектура

## Слои

```
screens / games / ui      React-экраны и мини-игры (только отображение и ввод)
        │ useApp(): { store, api, svc, audio }
app/                      bootstrap, навигация, уведомления, баннеры
        │
game/api.ts               единственная точка входа для действий игрока
game/engine/*             чистые правила: экономика, гардероб, база, уровни, квесты, сундуки…
game/data/*               контент (данные), без логики
        │
game/engine/store.ts      GameStore: транзакции и подписки
storage/*                 SaveService, IndexedDB, экспорт/импорт, миграции
```

UI **не изменяет состояние напрямую** — только вызывает `api.*`. Правила не знают про React.

## Транзакции

`GameStore.tx(fn(draft, ctx))`:
1. клонирует состояние → `draft`;
2. выполняет действие; ошибки правил — `GameError` с понятным русским текстом (интерфейс показывает его тостом), состояние при этом не меняется;
3. крутит цикл событий (не более 8 проходов): действия порождают события, на них реагируют задания, достижения и пересчёт прогресса;
4. `normalizeRooms`, `assertWalletValid` (валюты — неотрицательные целые), `revision++`;
5. публикует новое состояние и ставит запись в очередь `SaveService` (только в режиме `main`).

## Экономика

Все изменения валют идут через `engine/economy.ts` (`earn`, `spend`, `canAfford`), которая:
- запрещает отрицательные балансы и дробные значения;
- ведёт журнал операций и пожизненные счётчики;
- не позволяет обойти проверку из экранов.

Награды за попытки идемпотентны: `metadata.processedEvents` хранит идентификаторы `run:`/`arcade:`/`cook:` и `openId` сундуков (см. [SAVES.md](SAVES.md)).

## Случайность

Сундуки и события используют `mulberry32` с состоянием в `metadata.rng`. Результат открытия детерминирован относительно сохранённого состояния и `openId`: перезагрузка посреди открытия не даёт «переролла».

## Песочница

`enterSandbox`/`exitSandbox` подменяют состояние копией в памяти (с открытыми вещами). В режиме `sandbox` запись в хранилище отключена, баннер сверху напоминает об этом, экран сохранений заблокирован. При выходе возвращается настоящее состояние.

## Графика

Один рендерер `art/` рисует Нанабо слоями (тело, лицо, одежда, обувь, украшения, аксессуары, очки, шапка, эффект), иконки вещей и декор базы. Тот же рендерер используется в магазине, гардеробе, фото, играх и иконках PWA (`scripts/gen-icons.tsx`).

## Мини-игры

Контракт: `GameResult { success, metric, note? }`. Смысл `metric` задаёт правило звёзд уровня в `game/data/worlds.ts` (бананы — больше лучше, ходы/ошибки — меньше лучше, и т. д.). Один и тот же игровой компонент работает и в уровне, и в аркаде (`games/arcadeConfig.ts`); «Хаос на базе» — последовательность этапов с сердечками.

## Навигация

Стек экранов (`push/pop/replace/reset/popTo`) + вкладки. Реестр `ROUTES` — единственный список экранов; тест `routes.test.ts` проверяет, что каждый `nav.push(...)` в коде указывает на существующий маршрут (нет «мёртвых» кнопок).

## PWA

- `scripts/build.mjs` (esbuild) собирает `dist/`: хешированные файлы, относительные URL (работает из любого подкаталога), `version.json`.
- `sw.template.js` → `dist/sw.js`: **полный предкеш** всех файлов версии (`cache.addAll` атомарен: версия либо установлена целиком, либо нет). Новый воркер ждёт; включается только по сообщению `SKIP_WAITING` после нажатия «Обновить». Старые кеши удаляются при активации.
- Офлайн: навигация отдаётся из кеша, внешних запросов у игры нет.
- `manifest.webmanifest`: `standalone`, `lang: ru`, иконки 192/512/maskable и `apple-touch-icon`.

## Тесты

| Уровень | Где | Что |
|---|---|---|
| unit | `tests/unit` | данные, экономика, награды, гардероб, уровни, рендер, правила игр, маршруты |
| integration | `tests/integration` | SaveService: запись/чтение/откат/копии/импорт/восстановление |
| migration | `tests/migration` | миграция реального старого файла без потери данных |
| e2e | `tests/e2e` | Playwright: установка, офлайн, подпуть, обновление, импорт/экспорт, уровень |

`tests/e2e/run.mjs` собирает две сборки (A и B) с разными метками и поднимает сервер под `/stefania-nanabo-world/`; тест «обновление» переключает сервер с A на B, чтобы настоящий Service Worker увидел новую версию.
